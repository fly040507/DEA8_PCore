本文件覆盖 A/B 旧方案中关于“11级 DEQACC、无前递”的假设。其它更新规则如下：

- 数据面只认识 `compact row=0..M-1`；原始 token 行号保留在控制上下文。
- K/V projection 固定 51 行；其余五种 job 使用动态 M。
- PE 每个 bank 只存本 PE 的一个 INT8 B 权重，双行 A 共享该 B；两个 bank 共两个权重。

- 当前 DEQACC 的 Ea/Eb/fold 必须逐事务捕获，不能按整个 job 固定。
- 本版借用旧方案的模块职责和数据路径，运行时行数与流水完成边界按新基线适配。

## 2. 整体复用原则

动态 M 的主要变化是工作范围：存储最大容量仍按 51 行配置，计算速率和数据宽度保持；只访问前 M 行、发射有效 pair、传输有效数据，并按最后一次有效提交结束。

```text
DEA8 job
  -> Pcore Control：锁存 effective_M、profile、operation、事务身份
  -> Projection / Attention / G-U adapter
  -> 新 A queue + 新 B loader
  -> 原双行 PE/MXU 算术
  -> 新七级 DEQACC + 完整 FACC-A/FACC-B/OACC
  -> 原 VPU/SFU 接口与后处理控制
  -> QOZ/PBUF，或 PCore 内部输出模块
  -> K/V 直达 Gcore；O/Down 经 Reduce 到 Gcore
```

复用分四类：

| 类别 | 含义 |
|---|---|
| 直接复用 | 算术/功能与 M 无关，接口兼容后不改变主体 |
| 动态适配 | 保留结构，增加 M/context，改计数、mask、边界及提交条件 |
| 接口改造 | 算术保留，但加载/存储物理接口已经改变 |
| 替换或退出主路径 | 被新 A/B 或 DEQACC 结构承担，旧文件只用于参考回归 |

“复用结构”不等于原文件逐字复制。固定 `ROWS=51` 的最大容量仍保留，但固定 `PAIRS=26` 的运行次数必须移到 job 上下文。

## 3. 统一动态上下文与地址

### 3.1 运行参数

```text
MAX_ROWS     = 51
effective_M  = K/V ? 51 : job.dynamic_M
pair_count   = ceil(effective_M / 2)
row          = 0 .. effective_M-1
pair         = 0 .. pair_count-1
pair_valid[p][r] = (2*p+r < effective_M)
```

保留 6-bit 行数、5-bit pair 序号的容量即可覆盖 51 行。M=0 先单独走空任务完成分支，不计算 `pair_count-1` 或 `M-1`；M>51 是非法命令。

统一锁存：job token、effective_M、profile_id/version、data_context、source、layout、输出目标。Pcore 将这些信息下发到矩阵、后处理、存储 acquire、外发和完成检查中。不能只在 matrix 顶层加入 M，后处理仍然运行 51 行。

### 3.2 保留原 ACC 地址布局

FACC/OACC 继续按 compact pair 和原固定列 stride 寻址：

```text
FACC physical address = pair
OACC physical address = pair * 16 + n_tile
```

物理地址不因 M 改变而重排。VPU-facing tile-major 地址如果使用运行时 pair_count，必须显式转换：

```text
pair  = logical_addr % pair_count
tile  = logical_addr / pair_count
physical_addr = pair*16 + tile
```

M=0 不执行这段除法。不能把物理 stride 16 改成 pair_count，也不能一端按最大 26、另一端按动态 pair_count 理解同一个地址。

### 3.3 原始行号的边界

PE、MXU、DEQACC、FACC/OACC、SBUF、Pair Buffer、PBUF、QOZ 都只使用 compact row。RoPE 命令引用 row profile 和 position_base，由控制上下文提供对应的实际 position。

Gcore 按 transfer context 找回 compact→original 映射；不在外发每行 payload 中重复原始行号。若 Attention mask 本身依赖 query 的原始位置，由上游准备对应 compact mask/context；矩阵算术无需知道 original row。

## 4. PE 与 MXU 的复用

### 4.1 PE：直接复用

基线：`DEA8/Pcore/rtl/dea8_pe_2row.sv`。

每个 PE 保留：

- 两个 8-bit 驻留 B weight bank。
- 一个 DSP48E2，处理共享 B 的双行 INT8 乘法。
- packed product 的拆包、符号处理和高半修正。
- 两个 INT16 product 输出及原乘法/拆包延迟。
- `load_we/load_bank/load_weight`、`active_bank`、`mul_en`。

PE 不保存 original row、M、scale 或 tag。M 小于两行时无效 A lane 输入确定值，后续 row_valid 禁止它写回。M=0 时不启动 PE。

四列/拍加载由 MXU 外围分发到 64 个 PE，每个 PE 仍一次写一个字节。没有必要把单 PE 写口扩大为两列或四列，也不需要增加 DSP。

### 4.2 MXU：算术复用，加载边界改造

基线：`dea8_mxu_2row.sv`。

保留 16×16 PE、双行广播、Q_ACT_REG、乘法拆包和四级加法树：

```text
S0  Q_ACT_REG / metadata
S1  DSP multiply
S2  product unpack
S3  16 -> 8
S4   8 -> 4
S5   4 -> 2
S6   2 -> 1，直接写 Psum 输出寄存器
```

旧代码已有四级结果直接进入 `psum_reg`；不增加额外 Psum 结果队列来适应 M。

旧 MXU 的 `load_column + b1_t` 每拍只有一列，需要改成四列数据和列组写使能。`E_STAT_BANK_A/B` 保留在 PE 外，改为接收 tile 的 128-bit scale 向量。算术 PE 不变，外围 generate 的权重分发和 scale 写入接口改变。

保留随 Q_ACT_REG 同步捕获的 A scale、B scale、row_valid 和 compact tag。按当前双行 RTL，MXU 有七个 valid/sideband 位置 `[0:6]`，与 S0..S6 对齐；这一点不受 DEQACC 从11级变7级影响。

正常启动顺序：A data 写 Q_ACT_REG 的同沿，A scale、active B scale 和本次 tag 进入 sideband[0]。不得因为 B scale 提前装好而提前推进旁带。

### 4.3 bank 的实际释放

保留“最后一次 S1 乘法使用权重后，旧 bank 才可重写”的机制。最后一次 A 进入 S0 不等于 B 已经使用完毕。

新 B loader 的四拍写入和最后写拍 look-ahead 按 B 方案接入；完整 bank READY 包含 data、scale、descriptor。不能只复用旧 tile_idx 奇偶判断而忽略当前 bank 是否仍被引用。

## 5. DEQACC 七级替换方案

### 5.1 实际迁移的模块

从 `DEQACC/Pcore/rtl` 选择以下实现，后续迁移到动态工程时保留其功能合同：

| 文件/模块 | 功能 |
|---|---|
| `DEQACC_V1.sv` | 当前七级顶层、完整 ACC 接口、四组静态分发、commit |
| `deqacc_v1_pkg.sv` | key、地址函数、七级定义 |
| `deqacc_v1_control.sv` | valid、rows、完整 metadata 同步及 generation |
| `deqacc_v1_group8.sv` | 每组两行×四列、局部 key 和 A3/C 前递 |
| `dequant_lane_v1.sv` | Q0/Q1 反量化 |
| `fp32_add_lane_v1.sv` | A0..A3 精确 FP32 加法 |
| `acc_slice_v1.sv` | 单套完整16列 FACC/OACC 的存储组织 |
| `dea8_acc_store.sv` 中的 `dea8_acc_bank` | 当前 ACC RAM 依赖；使用 DEQACC 副本的 WIDTH 等端口定义 |
| `dea8_fp32_pkg.sv`、`pcore_pkg.sv` 的相应定义 | 数值函数与接口依赖，逐项合并后再编译 |

`DEA8` 的旧 `dea8_acc_bank` 接口缺少新版本使用的 WIDTH、SHARED_VALIDITY 等定义，因此不能只拷贝七级顶层而混用所有旧依赖。

新 `acc_slice_v1` 已经拥有完整 ACC。动态 matrix 不再额外实例化一份旧 `dea8_acc_store`；FACC/OACC 是一套物理存储，不是七级前后各一份。

### 5.2 七级具体职责

| 阶段 | 运算与存储联系 |
|---|---|
| Q0 | 捕获 Psum、Ea/Eb/fold、row_valid/key；计算幅值/lead/base；寄存 ACC 读控制 |
| Q1 | 形成 FP32 dequant partial；同步 ACC 读取由已寄存 Q0 驱动并返回 |
| A0 | 选择 old：A3 最新前递、C 前递、RAM old 或 add_old=0 的零值；分类、大小数选择 |
| A1 | FAR/CLOSE 对阶及加减 |
| A2 | 精确规格化，当前实现使用 LZD |
| A3 | RNE、特殊值、指数修正，得到最终 FP32 候选 |
| C | 将 A3 结果写回完整 ACC，同时产生 commit/data/meta/last |

32 lane 分为4组，每组两行×四列。每组结果为256 bit，四组静态对应原1024-bit双行结果；组划分不增加流水级、不产生四份 ACC。

时序定义：输入在边沿 t 进入 Q0，在 t+6 的 C 边沿提交，计为七个有效阶段。上层同步模块在后续边沿消费 commit；不要把端口采样边沿差与七级定义混用。

### 5.3 scale 与精度复用

输入保留 Psum INT32、Ea 两个8-bit、Eb 十六个8-bit、fold 和原数值编码。Q0 局部计算：

```text
base = Ea + Eb + fold - 266
```

Ea 可每个 row pair 改变，Eb 可每个 B tile 改变，fold 也必须随该笔 response 走。当前 `dequant_lane_v1` 的 base 寄存器为 signed 12 bit；不按草案中的10-bit建议擅自缩窄。

保留当前实现的 RNE、INT_MIN、bad scale、normal/subnormal、溢出和 signed-zero 处理。保留 shift=32 的专项 sticky 处理；不得只移植通常范围的快路径。

当前 FPADD 采用精确 LZD，没有实际实现 USE_LZA/LZA 预测与修正。LZA 和额外 scale 布局优化是 DEQACC 后续项目，不列入本轮复用已完成内容。

### 5.4 前递和动态 M

七级有 A3/C 前递，因此旧11级关于“必须等 RAM 全部写回才能再次累加”的约束被更新为：

```text
同一有效 parity、同一 ACC bank/address/generation 的依赖输入间隔 Delta >= 4
Delta=4：可取 A3
Delta=5：可取 C
Delta>=6：依赖正确对齐的同步 RAM 返回
```

新 RTL 对 Delta<4 的拒绝主要是仿真 assertion，没有自动在硬件输入端暂停的 ready。Pcore 矩阵调度必须在启动/issue前遵守该条件。

动态版沿用累加顺序，不为绕过依赖而重排 FP32 求和。对同一 FACC 的相邻 KTile，启动间隔至少四拍；P=1/2/3 时不能仅用“B 长期平均4.25拍”证明安全，因为初始双 bank/queue ready 可能造成短间隔突发。

以四拍为保底的启动检查与新四拍 B loader 相容。预留整 tile 后连续发射，避免发到一半才因 DEQACC 输入没有 ready 而停顿。GU/PV 按实际 acc_sel、addr、有效 parity 检查，不给所有不相关地址强行添加统一暂停。

### 5.5 外部 ACC 读写

七级顶层保留 result read、VPU write、commit 和调试接口，可与旧 PCore 接口对接。但新 `result_free/vpu_free` 会检查该 bank 的全部在途事务，外部读取/缩放只能在该 bank 可用时握手。

这是生命周期条件，不根据一个固定计时器假定 ready。不同 bank 的后处理可并行；同 bank 的矩阵与 VPU 不同时占用。同步 ACC 读从已寄存 Q0 驱动的对齐保持，不提前到输入接受沿。

### 5.6 新旧延迟更新

动态工程中统一定义 `DEQACC_PIPE_STAGES=7`；GU capture、result read、done 和尾部控制引用真实 commit，而不是继续等待旧11级常量。

从 MXU S0 到新 DEQACC C：当前寄存边界为 S0..S6，MXU response 在下一边沿进入 Q0，再经 Q1/A0..A3/C，最后提交在首 S0 后13个边沿。相较旧11级减少4拍，但不据此删掉其它真实握手。

Attention 名义 block 预算可沿原定义使用 `16*pair_count + 6 + 7 + block_margin`。B带宽、小M的Delta=4、冷启动、job交接还需分别计入；该表达式不是所有M的真实仿真周期。

### 6.1 valid 和初始化

每次任务建立 active_M、owner/profile/version 和有效状态。M减小后旧payload可以保留；M重新变大时新增行不能自动有效。

FACC 第一KTile用 `add_old=0` 覆盖有效行，后续才累加。PV(0)建立初始OACC，后续PV在缩放已提交后再累加。workspace 的行最大值、行和和缩放状态按旧算法初始化，限于有效行。

clear/reset 继续清valid和流水，不要求清大RAM。job错误/cancel必须使整个输出不可提交，并排空旧返回。新DEQACC一位内部generation是局部流水身份，不替代Pcore完整token和flush协议。

### 6.2 A/B queue 与 ACC 的清理分开

不能为了换一个A/B segment或重置运输序号就清整个DEQACC，否则跨K累加或跨PV的OACC会被破坏。分开管理source reset、slot/bank释放、operation clear和job取消。

## 7. 三类矩阵计算与七种 job

保留三个 algorithm adapter 共用一个 matrix execution core，七个job职责不变：

| Job | A/B来源 | 有效行 | 保留的计算/输出链路 |
|---|---|---|---|
| K | XBC/HBM | 51 | K projection→RoPE→量化→K sender |
| V | XBC/HBM | 51 | V projection→token-B16量化/重排→V sender |
| Q | XBC/HBM | M | Q projection→RoPE→量化→QOZ_Q |
| Attention | QOZ_Q或PBUF/KVB | M | QK/PV交替→在线softmax/OACC→A_FIN→QOZ_O |
| O | QOZ_O/HBM | M | O projection→FACC→Pcore输出→Reduce |
| G-U | XBC/HBM | M | G/U交错→Pair Buffer→GELU/乘法/量化→QOZ_Z |
| Down | QOZ_Z/HBM | M | Down projection→FACC→Pcore输出→Reduce |

固定feature/K/N几何继续沿旧设计：Q/K/V reduction为64 tile，O为16，Down为32；每核GU输出32个NTile、每个NTile包含64 Gate与64 Up tile。M只改变行，不改变这些feature维度。

### 7.1 Projection

复用 `dea8_projection` 的跨NTile工作组织、FACC-A/B ping-pong、当前结果读出与下一NTile计算重叠、后处理退休。

适配全部读写pair计数、动态last和mask，传入真实M。旧文件的 `service_req.rows=ROWS`、固定26次读出和局部源读取改为当前有效值。保持partial FP32先完成累加再交后处理；不在每个KTile重复量化。

### 7.2 G-U

复用 Gate/Up role、独立FACC-A/B累加、最终K结果捕获到Pair Buffer、后处理与下一NTile计算重叠。新A queue保存一个A切片，依次给G(k,n)、U(k,n)使用；旧A replay缓存功能退出主路径，避免同一A再存一份。

Pair Buffer继续每拍读一行Gate和对应Up，M行最多M个有效输出握手，不为省一半拍数扩展成双行结果buffer。`first/second`这里是G/U操作数，不是32个Z结果。

旧Pair Buffer的complete条件依赖“第25pair、奇数尾行01”。动态版改为两分支当前有效行全部capture完成；M为偶数的尾部11和M=1的尾部01都必须完成。

保留先消费Pair Buffer、再等待VPU量化Z提交和post done的区分。GELU/SFU、FP32乘法/VPU的真实实现由负责人接入；Pcore传M、elements、token、数据和完成约束。

## 8. Attention 调度保持旧实现的真实顺序

旧 `dea8_attention_job_adapter` 实际使用 `dea8_attention_scheduler_v4`。后续借用该实现的descriptor/依赖机制，不由文件名新增设计版本。

实际110个矩阵子任务顺序：

```text
启动：QK(0), QK(1), PV(0)
稳态：QK(b+1), PV(b)
末段：QK(54), PV(53), [额外一个block级缩放窗口], PV(54)
尾部：RECIP, A_FIN/量化，O写入QOZ
```

这里没有QK(55)。上一轮文字中写成单纯 `QK0→PV0→QK1→PV1` 的描述不符合旧RTL；本版按实际lookahead启动和交替顺序复用。

保留：一个current/一个pending矩阵descriptor，prefetch与execution grant分离；QK/PV有序完成；P_READY、SCALE_READY、PV_COMMITTED；alpha两代；PBUF ping-pong；VPU/SFU独立命令及完成事件。

### 8.1 动态范围

QK(b)为 `[M,256]×[256,16]`，沿K分16次；PV(b)为 `[M,16]×[16,256]`，沿N分16次。有效issue均为 `16*ceil(M/2)`。

55个key block继续保留，M改变query/action的行数，不改变完整KV和prefix/suffix key block的数量。block_id、nt、FACC/OACC角色与旧方案一致。

`dea8_attention_matrix` 去掉只接受 `cmd.m_rows==51` 的限制，源完整性检查加入M/profile；Q读取和P replay切换按新A存储接口完成。

### 8.2 非矩阵隐藏

在线流程保持：QK commit→mask/行最大值/aa→alpha→exp(S-row_max)→行和更新与量化P→PBUF commit；旧alpha缩放OACC，PV把当前block贡献加到OACC。

在理想32-data/拍模型下，M×16工作按双行分组约需pair_count个数据拍，M×256约需16×pair_count个数据拍。M减小会同步减少非矩阵工作，继续使用原隐藏窗口和ready/done依赖。

SFU的当前control TB仍按4 lane建模，workspace每个端口为16个FP32。真实SFU/VPU主动适配的设计要求可以保留，但必须用实际接口服务和流水延迟统计，不把所有端口都写成32-result/拍。固定握手/管线开销单独计入。

### 8.3 尾部与完成

PV(53)→PV(54)额外等待窗口保留，长度由当前M对应的block预算传入，不能继续固定旧416/434/433拍。窗口结束同时还要满足最后PBUF已提交、最后OACC缩放已提交。

PV(54)完成后，reciprocal只处理前M行，A_FIN处理M×256输出并量化写O。M=0整个Attention空完成，不执行110个空子任务，也不求不存在的1/l。

done分别表示：最后结果已写入SBUF/PBUF/OACC/QOZ等目的存储，而不是最后请求刚发出。七级缩短提交延迟，依赖检查仍由事件驱动。

## 9. 后处理、VPU/SFU及workspace

复用 `dea8_pcore_post` 的RoPE两特征tile配对、G/U配对、V转置token量化布局；复用 `dea8_pcore_workspace` 的两代score/alpha与行状态。

动态适配范围：

- command中elements、M/profile、尾部有效mask。
- Q的RoPE position来自profile；K仍为完整identity行加position_base。
- 一般feature-B16量化每行16个INT8和一个scale，数值定义不改变。
- V仍按完整51行的token-B16分组，最后组padding保留。
- workspace行span的mask限于M；读一行Score的16个列仍有效，不能把M当列mask。
- AFIN、P_POST、QK_POST、SCALE的写入完整性检查从51行变为当前M行。

保留每个unit一个inflight command、token回显、请求response credit、有效payload保持、独立drain和flush ack。内部算法实现不进入本方案的Pcore修改范围。

现有GU post service按一行事务等待GELU返回，再送VPU；RoPE的两份16元素是同一行两特征半部。这些现有服务方式可复用，不能单凭1024-bit端口断言每拍产生32个独立结果。若它们在动态版实测仍能隐藏，不增加复杂buffer；若成为限制，再局部流水化该适配器。

## 10. Pcore控制、协议和所有权

`dea8_pcore_control`继续接DEA8总控的七job；`dea8_pcore_exec`组织三adapter和共享fabric；`dea8_pcore_ctrl`负责operation owner和完成/错误归属。Pcore不自行理解十步/18层。

复用这些机制并把M/profile贯穿：job合法性、源context前置条件、QOZ acquire/release、post command、ACC地址转换、units token、cancel、迟到返回、flush、外发退休。

`engine_job`目前只复制header，动态版必须把运行参数传入所有子模块，避免外层知道M而adapter仍强制51。profile可以用引用ID代替每个micro-op重复51个行号，但引用必须在job/存储/外发完成前保持稳定。

生命周期保持：Q producer acquire→量化commit→Attention consumer→释放Q→O producer→O projection consumer→释放O→GU/Z producer→Down consumer→释放Z。

M/profile变化不能复用另一个profile下的Q/O/Z有效状态。M=0动态job直接空完成，但还要执行必要的控制退休；不能留下旧owner让下一个正常job被永久阻塞。

## 11. 传输线宽与返回识别

| 路径 | 保留/新宽度 | 动态版处理 |
|---|---|---|
| XBC→Pcore | 新384-bit数据+24-bit scale+transport | 按A方案，三compact行/beat |
| HBM/KVB→Pcore | 新512-bit数据链路 | 按B方案，布局和身份原子检查 |
| A queue→Q_ACT_REG | 两行256-bit INT8+16-bit scale+tag | 宽度保留，只发pair_count拍 |
| MXU→DEQACC | 1024-bit Psum+144-bit scale+row_valid/meta | 原双行格式复用，逐事务对齐 |
| 每DEQACC算术组↔完整ACC | 256-bit双行四列bundle，共4组 | 静态分割/拼接，不加hidden stage |
| 完整ACC↔VPU/结果reader | 两行×512-bit FP32+context | 复用，增加动态范围检查 |
| workspace↔VPU/SFU | 每端口16×32-bit+mask/token | 复用两个独立访问接口 |
| VPU量化结果 | 两个136-bit row entry+mask/context | 适配写入QOZ/PBUF三bank，连续双行无bank冲突 |
| Pair Buffer→post | Gate 512 bit+Up 512 bit | 一行G/U操作数，传M次 |
| Pcore→Gcore K/V | 128-bit header，136-bit payload | 保留K51/V64个传输word和commit |
| Pcore→Reduce | 128-bit header，512-bit payload | 输出M行，保持单行/beat |
| Reduce→Gcore | 128-bit header，512-bit payload | 输出M行，保留tile commit |

原宽度不变的传输只缩短有效次数，valid停顿时data/scale/tag/last保持。串行化输出的cycle包括握手和阶段切换，不能直接把M个payload beat当成M个总cycle。

### 11.1 K/V外发

复用 `dea8_kv_tile_sender` 的64×136-bit tile RAM、FILL/SEND/WAIT_COMMIT和检查。K一个tile51word；V转置token-B16布局仍是64word，其中含padding，不因动态Q行数变成Mword。

每核仍处理K/V各32列、两个16列tile；K的非连续特征列坐标及V的列坐标保留原header生成规则。跨核拼接由Gcore承担。

### 11.2 O/Down外发与Reduce

PCore继续从最终FACC读出，再经内部输出模块发给Reduce，不新增完整FP32输出tile副本。读取/输出可与下一NTile计算并行，FACC复用必须等待该结果读出引用解除。

O/Down header.rows改为M，row/pair/last和本核输出完成计数动态化。Reduce输入八核必须使用同一M、profile、tile、目标context；不能只逐核通过范围检查就归约不同的token集合。

128-bit tile header主体可保留。V1优先用现有transfer_id/transfer_epoch/destination_id作为不可变profile映射的查询键，在总控/Gcore建立对应关系；token_origin只对连续序列有直接base意义，非连续profile不能按token_origin+local_row回填。若接收端不能查询该context，才明确协商新增profile字段，而不是每行附加original_row。

Reduce树及512-bit数据口复用；接收、issue、结果写入、send、last及八header一致性改为动态rows。结果RAM容量51行和各输入FIFO深度8保留。

PCore本核O/Down完成：最后一个输出beat已被Reduce接收且本核内部排空。全局完成：Reduce结果已被Gcore commit。DEA8总控继续区分这两个事件。

## 13. 证据边界与后续验证

本轮检查的是方案、当前RTL实例、端口及既有验证记录，没有重新运行仿真/综合。

独立DEQACC的2026-10-13记录包括：211978笔反量化/FPADD、10486笔七级流水commit、Delta4/5/6/7、A3/C命中、V1/V2同拍对照和完整七job FUNCTIONAL通过。详情见 [V2验证状态](../../DEQACC/Pcore/reports/v2_verification_status.md)。

该动态M测试仍使用旧加载链，最小地址复用间隔记录为17/26拍。因此不能把它当作新四拍loader与小M全链路已经通过的证据。七job记录也不是动态版PERFORMANCE、八核联调或250MHz布局布线签核。当前DEQACC尚无V2综合/P&R结论。

动态工程实施后的验收重点：

1. 全部M=0..51；K/V固定51；奇偶尾部、M=1以及小M→大M旧行不泄漏。
2. 新A/B已ready时短间隔启动，验证Delta4及违例1/2/3的明确拒绝；A3/C/RAM三类old来源。
3. 四列PE写入、E_STAT整向量、MXU七级scale/tag到七级DEQACC commit逐笔对齐。
4. Projection、GU、Attention的实际累加顺序和参考值，Pair Buffer偶数M完成，PBUF/GU复用不串role/block。
5. 完整Attention 55QK+55PV，启动顺序、PV53/54额外窗口、AFIN及QOZ_O提交，记录总job周期。
6. 七job与外部VPU/SFU/HBM/KVB TB联动；elements/expected_results/last全部按M，而非只测matrix少发几拍。
7. O/Down八核相同profile/M的Reduce，动态输出和Gcore映射；KV K51/V64word协议保留。
8. 背压、inflight、clear/flush、迟到单位返回和外发commit；完成不能早于目的提交。

执行顺序：先落实A/B与存储接口，再接当前七级DEQACC及依赖，随后动态化三个adapter/后处理/控制/外发，最后开展单核七job和八核Reduce验证。各层保留最大容量和当前运算结构，只有验证发现的局部瓶颈才进一步改造。
