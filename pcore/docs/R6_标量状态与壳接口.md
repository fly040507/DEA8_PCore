# 第六轮：标量状态、P 流与四个壳接口

## 1. 实现范围

本次不实现其他同学的 EXP、Reciprocal、Mask、量化或通用 VPU 算术。
完成的是 PCore 自己的状态存储、数据传输、命令和完成边界，以及独立仿真壳。

| 文件 | 属性 | 内容 |
| --- | --- | --- |
| rtl/dea8_attention_state.sv | RTL | m、aa、l、alpha 双代、recip_l 和访问检查 |
| rtl/dea8_p_result_link.sv | RTL | SFU 到 VPU 的单条目弹性 P 结果流 |
| rtl/dea8_attention_core.sv | RTL | 状态/P 流接入真实矩阵、调度和向量存储通路 |
| tb/stubs/dea8_vpu_stub.sv | 仅仿真 | 独立的 VPU 命令/完成和存储客户端模型 |
| tb/stubs/dea8_sfu_stub.sv | 仅仿真 | 独立的 SFU 标量、SBUF、P 流客户端模型 |
| tb/stubs/dea8_gcore_stub.sv | 仅仿真 | XBC、KVB K 固定数据源和 CNET 握手接收端 |
| tb/stubs/dea8_hbm_stub.sv | 仿真用途 | HBM 私有权重流固定数据源，8 数据 beat 加 1 scale beat |

四个壳不加入生产 RTL 的 dea8_pcore.f；run_xsim.ps1 单独编译它们。
VPU/SFU 模型采用等分数、定值输入测试，不是可用于任意模型的算术实现。
这两个模型仅支持上电复位，运行后再次复位会明确报错；真实 RTL 的复位测试由独立模块用例覆盖。

## 2. 实际标量存储

| 存储 | 数量 | 元素 | 容量 | 写入者 | 读取者 |
| --- | --- | --- | --- | --- | --- |
| m | 51 | FP32 | 204 byte | VPU QK_POST | VPU、SFU |
| aa | 51 | FP32 | 204 byte | VPU QK_POST | SFU ALPHA_EXP |
| l | 51 | FP32 | 204 byte | VPU P_POST | VPU、SFU RECIP |
| alpha_A/B | 2 × 51 | FP32 | 408 byte | SFU ALPHA_EXP | VPU P_POST、OACC_SCALE |
| recip_l | 51 | FP32 | 204 byte | SFU RECIP | VPU AFIN |

纯数据容量合计 1224 byte，另有写入位图、有效位、代际上下文和响应寄存器。
当前按寄存器堆表达，支持所需并行读口，不声称能直接推断成一块单端口 BRAM。
这些 RF 全部实例化在 Attention Core 内，不放进 VPU/SFU 壳内部。

一次 Attention start 被接受时，m 初始化为 FP32 -Inf，l 初始化为 +0。
aa、alpha、recip_l 通过有效位保护，不需要清空每个数据寄存器。

## 3. VPU 标量接口

所有行地址为 ROW_BITS=6，有效范围 0..50；FP32 数据为 32 bit。
读请求在上升沿采样，响应数据和 rsp_valid 在该沿之后有效，即同步一拍读。
没有响应 ready，发起读取前客户端必须保证接收能力。

- vpu_m_rd_en / row -> vpu_m_rsp_valid / data：读取旧行最大值。
- vpu_m_aa_wr_en / row / m_data / aa_data：同一沿原子写 m_new 和 aa。
- vpu_l_rd_en / row -> rsp：读取历史行和。
- vpu_l_wr_en / row / data：写 FP32 l_new。
- vpu_alpha_rd_en / bank / row -> rsp：读取本 VPU Job 对应代的 alpha。
- vpu_recip_rd_en / row -> rsp：读取最终 recip_l。

alpha 的 block/head/epoch 从已接受的 VPU Job 锁存，不根据当前矩阵 Job 推导。
QK_POST 才能写 m/aa；P_POST 才能写 l；P_POST 和 OACC_SCALE 才能读取对应 alpha；AFIN 才能读 recip_l。

## 4. SFU 标量和向量接口

| 接口 | 数据宽度 | 地址/控制 | 作用 |
| --- | --- | --- | --- |
| sfu_aa_rd | 64-bit 响应 | 6-bit 偶数 base + 2-bit mask | 每次读取 aa[base]、aa[base+1] |
| alpha_wr | 64-bit 写数据 | 同上 | 写入当前 SFU Job 预约的 alpha Bank |
| sfu_m_rd | 32-bit 响应 | 6-bit row | 与一行 SBUF 配对 |
| sbuf_rd | 512-bit 响应 | Bank + 6-bit row | 提供 16 个 Score |
| sfu_l_rd | 64-bit 响应 | 6-bit 偶数 base + 2-bit mask | 尾部读取两个 l |
| recip_wr | 64-bit 写数据 | 同上 | 写入两个 recip_l |

base 为 0、2、4、…、50。0..48 的 mask 必须为 11，最后 base=50 的 mask 必须为 01。
无效 Lane 的读响应固定为零，不能访问不存在的 row51。
这是 PCore 侧 RF 适配接口；若同学的 SFU 采用两个独立地址，后续在适配层转换，不改其计算单元。

SBUF 和 m 当前分别提供同步读口，SFU 壳发起相同 row 的请求进行配对。
正式实现仍需 SFU 或适配层的行缓存/预取，才能保证连续双 Lane EXP 的吞吐；
现有仿真壳逐行握手，不能把它的周期当作 408 拍的性能证明。

## 5. alpha 代际规则

SFU_ALPHA_EXP 命令接受后，记录写 Bank 和 block/head/epoch，开启一代写入。
51 个行位置各自只能写一次；alpha_end 可以与最后一次写同拍，必须累计覆盖全部 51 行。
只有完成后，alpha_ready 才置位。

同一代有两个消费者：
1. VPU_P_POST 使用 alpha 更新 l；
2. VPU_OACC_SCALE 使用 alpha 缩放旧 OACC。

两者都完成后才释放 Bank。Block0 不执行 OACC_SCALE，因此开始时将该消费者标记为已完成，
但仍须等待 P_POST 完成。这样可以保留下一块已经生成的 alpha，同时旧代仍等待缩放。
重复消费者完成、未写满就完成、提前覆盖和错误代际读取均有断言。

aa 在 alpha Job 完成后失效；SFU 消费期间禁止 VPU 写 aa。
recip_l 同样须写齐 51 行并完成，才允许 AFIN 读取；SFU 消费 l 时禁止 VPU 更新 l。

## 6. P 结果流

SFU -> P Link -> VPU。每次握手携带：

| 字段 | 位宽 |
| --- | --- |
| data | 64：两个 FP32 |
| block/head/epoch | 6 + 3 + 4 |
| row | 6 |
| pair_index | 3，表示 0..7 |
| lane_mask | 2 |
| last | 1 |

记录合计 89 bit，不含 valid/ready。P Link 保存一条完整记录并提供背压。
Mask 后的 P=0 仍是有效 FP32 结果，不应把该 Lane 当成没有发送的数据。
每个 Job 必须交付 51 × 8 = 408 对；last 仅出现在 row50、pair7。
VPU P_POST 命令先被接受，SFU 才开始发送。
SFU 结束表示最后一对结果已交给 Link；VPU 结束还必须保证最后一对已消费及 PBUF/l 写入已结束。
Link 检查流交付，最终 PBUF/l 写入完成仍是 VPU 的 done 契约，不能用 Link 完成替代。

## 7. GCore/HBM 壳的限制

GCore 壳保留 XBC=256+16bit、KVB=128+8bit 和 CNET=512bit 的方向与基本字段。
XBC/KVB/CNET 的数据传输条件包括 pipe_en，HBM 补给不受 pipe_en 控制。
CNET mode 从外部输入，不改成由 PCore 自己决定；CNET Tag 宽度是占位参数，必须按全局负责人的契约配置。
CNET 接收模型只计数，不实现 reduce/gather。

KVB V 打包仍未确认，GCore 壳默认遇到 PV 请求就报错，避免静默采用错误的 scale 布局。
V_COLUMN_PROFILE 参数仅是显式实验选项，不代表冻结方案。当前 55 对 QK/PV 集成仍用内部规范化 B 列流。
GCore/HBM 壳已做独立传输仿真，尚未与完整 PCore Top 接成全流程。
