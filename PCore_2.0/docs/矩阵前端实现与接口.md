# PCore 2.0 矩阵前端实现与接口

更新日期：2026-09-24。依据桌面的 `README_2ROW.docx`；AI意见作为实现评审输入，不作为测试结论。

## 1. 当前做到哪里

本目录独立于旧版实现。当前形成了可仿真的矩阵前端：

```text
GCore 2-row XBC ------------------------------+
                                              |
QOZ data/scale even/odd -- synchronous read ---+--> job-locked A source selector
                                              |             |
PBUF pingpong x even/odd -- synchronous read --+       context/order check
                                                            |
                                                   atomic A2 FIFO
                                                      288 x 64
                                                            |
                                              complete Tile reservation
                                                            |
                                                 Q_ACT_REG[2][16]
                                                            |
HBM payload -> 2-Tile assembler -> W FIFO -----+              |
                                              |              |
KV column stream ---------------> KV FIFO ----+--> B loader  |
                                                    |       |
                                              PE B banks A/B
                                              E_STAT banks A/B
                                                    |       |
                                                    v       v
                                                256 x PE2
                                             DSP multiply/unpack
                                                    |
                                         two sets of 16 reduction trees
                                                    |
                                  Psum[2][16] + E_STREAM[2] + E_STAT[16]
                                          + tag[2] + dest[2] + mask
```

HBM接口目前是已经返回、顺序正确的256-bit payload流，不是完整AXI读请求引擎。KV由外部提供已经排成列的136-bit entry。没有把结果用testbench直接注入MXU内部，也没有用理想乘法替换DSP48E2。

## 3. 数据格式

### A侧

- `data[0]`：偶数行，128bit，低8bit为k=0。
- `data[1]`：奇数行，128bit，低8bit为k=0。
- `scale[0]`与`scale[1]`各8bit，独立保存。
- `row_valid`正常为11；pair=25时为01，仅row50有效。
- `tile_idx`是当前job内0起始的执行Tile序号，不直接等于物理RAM地址。
- `slot`与`epoch`必须匹配已接受的job。epoch作为进入校验器的独立信号，不占用288bit FIFO entry。
- `reserved[1:0]`必须为0。

所有来源在valid且ready时完成一次传输。受反压时，发送方保持valid、payload与metadata不变。整个job期间不能切换A/B来源。

### B侧

一个W Tile的HBM有效输入：

1. beat0至beat7，每拍256bit，按行连续保存两个128bit权重行。
2. beat8，低128bit为16个输出列的scale；高128bit不使用。
3. assembler按输出列n依次生成`{data[127:0], scale[7:0]}`的`b_t`；其中data包含k=0至15的16个权重。
4. W FIFO每项136bit，loader连续16拍写入PE驻留Bank及对应E_STAT列。

KV路径绕过W转置缓存，直接提供同样的136bit列entry。两条B路径分别有一个136×64 FIFO，仅当前job选中的路径被消费。

这里按新的2-row README保留BEntry逐列装载。**不是旧讨论中“E_STAT全部提前一拍写入”的实现**：本版每拍随一个B列写入一个8bit scale，16拍完成整个E_STAT Bank。

## 4. QOZ/PBUF的物理组织

默认QOZ：32个Tile位置；每个位置有26个row-pair。

```text
even data RAM  : 832 x 128bit
odd  data RAM  : 832 x 128bit
even scale RAM: 832 x 8bit
odd  scale RAM: 832 x 8bit
```

PBUF：两个Attention pingpong Bank，每个Bank内再按奇偶行分开。每个奇偶data RAM合计52×128bit，每个奇偶scale RAM合计52×8bit；pingpong Bank编码在地址中。

通用地址：

```text
address = (pingpong_bank * PAIRS + row_pair) * MEM_TILES + memory_tile
```

RAM是同步读，接收请求的上升沿之后产生对应输出寄存器内容；下一模块在后续上升沿接收。输出valid会在反压下保持，不覆盖尚未被A2 FIFO接受的数据。无反压时可每拍完成一个双行读。

写接口固定绑定奇偶lane：

- 偶数行单写：mask=01，数据放lane0。
- 奇数行单写：mask=10，数据放lane1。
- 两行同时写：mask=11。
- row50只允许mask=01。

README建议中“一行结果永远mask=01”不能直接套用固定奇偶lane，本实现作了上述澄清。

每个地址有初始化标记；未写好的有效行不允许读出。clear清除初始化标记和输出valid，但不逐位清RAM。read/write命中同一地址时暂缓读请求，避免依赖器件的read-during-write模式。

每个物理Bank另有 `open_bank`、`complete_bank`、`bank_epoch`、`region_base` 和 `region_tiles` 状态。生产者必须先发送 `begin_bank(valid, bank, epoch, tile_base, tile_count)`，随后只在 Region 内写入全部有效地址，再发送参数一致的 `commit_bank`；只有计数完整且 epoch、base、count 均匹配时才置 `complete_bank`。Reader 的 `rd_ready` 同时检查 complete、epoch 和 Region 范围，因此旧数据不会因为初始化标记仍存在而被误读。begin/commit 同周期、错误 Bank、Region 外写、重复写、未写完整或描述不一致都会置 `protocol_error`。

QOZ物理容量固定为32 Tile，但有效 Region 可以小于物理容量：Q/O通常使用 `tile_base=0,tile_count=16`，Z通常使用 `tile_base=0,tile_count=32`。Z→Q复用时，begin新epoch会立即使旧Region不可读，commit后只恢复新Region的可读范围。PBUF的执行job可以有多个输出Tile，但物理上重复读取一个Tile，所以启动检查只要求所选PBUF Bank的一个物理Tile已提交。

PBUF某一Bank何时属于producer、何时属于consumer，仍由未来Attention控制器管理；本版的 begin/commit 只提供硬件可检查的生命周期边界，不能替代上层对 consumer 完成时间的管理。不能在consumer尚未读取完时覆盖同一个逻辑Bank。

## 5. Job接口与调度

`job_valid && job_ready`接受一个job，内部锁存配置，直到done或clear：

- `a_source`：XBC、QOZ、PBUF。
- `b_from_kv`：0选择HBM/W，1选择KV。
- `tiles`：1至64个执行Tile。
- `epoch/slot/head`：上下文。
- `along_n=0`：随Tile推进K坐标，适用于Projection/QK分块。
- `along_n=1`：随Tile推进N坐标，适用于PV分块。
- `kt_base/nt_base`：tag的逻辑坐标基址。
- `dest_base/dest_stride/dest_bank`：每个输出向量的目标描述；并不在本阶段实际执行写回。
- `a_mem_base`：QOZ物理Tile起始位置；与tag坐标基址独立。
- `pbuf_bank`：本次PV从哪个PBUF Bank读取。
- `init_dest`：目标累加器初始化控制。为1时，本 job 的首个逻辑累加片段带 `dest.zero=1`；为0时表示继续累加。它与 `along_n` 独立。

Matrix Engine 在 `job_valid` 阶段检查所请求的 QOZ Region 是否被已提交 Region 覆盖，并检查 epoch；PBUF job 检查所选 Bank 是否存在已提交的物理 Tile。结构非法配置会锁存 `protocol_error`；但 Region 尚未 commit 或 epoch 尚未匹配时只表现为 `job_ready=0`，不会生成错误，直到 Region ready 后再接受同一个保持有效的 job。这样 Projection producer 和 Attention scheduler 可以异步交接。

QOZ Reader按Tile推进物理地址；PBUF Reader在不同输出Tile间重复读取同一个P块。

Tile启动条件：

```text
A2 FIFO内有完整26-entry Tile
AND 对应B Bank完成16列加载
AND Tile序号匹配
```

B loader只在FIFO中至少有16列后开始装载，因此装载过程中不需要等待外部HBM/KV。A同样在启动前预留完整Tile。短期外部气泡只可能导致Tile启动等待，不会造成Tile内部断供。

当前选择保守的一拍Tile交接空隙，不追求零gap。在A/B均就绪时，输入端26拍有效、1拍交接，Tile起点间隔27拍。启动、供数等待、末尾冲刷另算；不能把26拍称为完整job耗时。

为切断 `job -> source selector -> A RAM ready -> A2 FIFO ready` 的组合路径，adapter后增加两项深的 `dea8_a_source_stage`。它只缓存完整的 `a2_t`，不改变 Tile 顺序；输入 ready 只看本地占用，因而不会把下游反压直接传回同步 RAM。该暂存级允许保守的一拍交接空隙，保持控制简单。

特别注意：最后一次A输入是在S0被捕获，PE在下一拍S1才实际用到对应B。旧Bank在最后一次S1乘法完成时才释放，不能在最后一次S0就立即允许覆盖。下一Tile可使用另一Bank，旧Tile后面的解包/归约树继续运行。

`done`在最后一个双行响应被内部完成逻辑观察到后脉冲一拍；当前下游没有ready，所以未来后端必须保证每拍接收双行结果，或在Tile预留条件中增加后端容量保证。

错误epoch、输入顺序等使protocol_error保持，需clear。地址和tag坐标越界的job拒绝执行。当前没有自动超时重试或重新请求HBM。

clear是整个矩阵前端的取消边界，不是外部HBM事务取消协议。上游必须停止/丢弃旧job尚未返回的HBM或KV payload，再提交新job；当前B输入没有AXI ID或epoch，不能自行识别取消前迟到的B数据。QOZ/PBUF的生产者也必须保证版本完整后再启动消费，不能仅凭旧初始化标记就复用未更新完成的Bank。

输出地址在Tile开始时装入基址，之后每个row-pair按`2*dest_stride`递增；奇数lane在偶数lane地址上加一个stride。这样避免每拍进行`row*stride`通用乘法。控制/地址层禁止隐式DSP推断，显式的256个PE DSP实例不受影响。

## 6. 7级流水的精确解释

以某个row-pair写入Q_ACT_REG的上升沿为t0：

| 上升沿之后 | 数据位置 | 旁带 |
| --- | --- | --- |
| t0 | Q_ACT_REG[2][16] | pipe[0] |
| t1 | DSP M寄存器，packed product | pipe[1] |
| t2 | unpack/correction，双INT16 product REG | pipe[2] |
| t3 | 第一级加法树16→8 | pipe[3] |
| t4 | 第二级8→4 | pipe[4] |
| t5 | 第三级4→2 | pipe[5] |
| t6 | 第四级2→1直接写双行Psum输出 | pipe[6] |

因此是**7个寄存器级、t0到t6跨6个时钟间隔**。下游若也是上升沿寄存器，则在t7捕获t6之后稳定的输出。这三种计数不能混用。

两行共享一组E_STAT[16]，各自保留E_STREAM、tag、dest和valid。scale与tag不进入PE，不参与INT8乘法；它们只随流水传递，留给未来DEQACC。

## 7. 逻辑存储量

下表是payload容量，不是BRAM/FF最终占用承诺；完整物理映射以相应层级综合报告为准。

| 存储 | 逻辑容量 |
| --- | ---: |
| 256个PE的两份INT8驻留权重 | 4,096bit |
| E_STAT双Bank | 256bit |
| 双行Q_ACT_REG | 256bit |
| 解包后的双行乘积寄存器 | 8,192bit |
| A2 FIFO | 18,432bit |
| W FIFO + KV FIFO | 17,408bit |
| 两份W Tile assembler缓存，含scale | 4,352bit |
| 默认32-Tile QOZ，含scale与无效尾行槽位 | 226,304bit |
| 双Bank PBUF，含scale与无效尾行槽位 | 14,144bit |

以上还未计入加法树、中间valid/tag/dest、RAM输出寄存器、FIFO头缓存、初始化标记等。

本次U50综合的集成顶层实际RAM映射如下：

| 存储 | RAMB36E2 | RAMB18E2 |
| --- | ---: | ---: |
| A2 FIFO | 4 | 0 |
| W FIFO | 2 | 0 |
| KV FIFO | 2 | 0 |
| QOZ even/odd data | 8 | 0 |
| QOZ even/odd scale | 0 | 2 |
| PBUF even/odd data，含双Bank | 4 | 0 |
| PBUF even/odd scale，含双Bank | 0 | 2 |
| 总计 | 20 | 4 |

即22个36Kb Block RAM Tile等效容量。逻辑容量不大不代表物理BRAM块数小，宽度、双行并行端口和data/scale分开存储均会增加碎片。当前对这些RAM显式要求block实现；PBUF的小深度scale RAM未来可评估改LUTRAM，但本轮未做。

## 8. 当前证据与边界

- 所有算术测试都使用实际DSP48E2仿真模型。
- 端到端矩阵前端测试使用真实HBM assembler、FIFO、驻留Bank、A侧RAM/reader、MXU。testbench只负责外部输入、初始化存储和独立的整数黄金比较。
- PE验证覆盖524,290组输入，不宣称穷举全部INT8三元组。
- 集成回归覆盖99个完整Tile、2,574个row-pair、82,368个Psum、未提交 Region 等待、`along_n=0/1` 下的 `init_dest=0`、1/64 Tile长度边界与一次运行中取消，不宣称已经跑通新版完整55-block Attention。
- 单MXU和矩阵前端集成顶层的本轮 OOC 综合展开都保持256个DSP。集成顶层报告为14,593 LUT、29,748 FF、20个RAMB36E2与4个RAMB18E2，4ns时钟下综合估计setup WNS为+0.668ns；Vivado 2022.2 在RTL优化结束后的 `.Xil/.../realtime/tmp` 清理阶段返回异常，但异常前已生成utilization、timing summary和checkpoint，因此这些数字是本轮 OOC 报告证据，不是布局布线签核。未完成布局布线、跨SLR检查、外部I/O时序约束、真实HBM流量测试和上板。
- 尚未实现双行DEQACC、FP32 accumulator奇偶分Bank及量化写回；这些是后续端到端吞吐的必要工作，不应把当前MXU提速直接当作整个VLA的2倍提速。

下一步先冻结双行Psum接收契约和每Tile下游容量保证，再实现双行反量化/累加；不要直接接旧版单行DEQACC并假设能够无损接收。
